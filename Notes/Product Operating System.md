# Product Operating System (POS) Playbook

> 这不仅仅是一份“一次性执行”的产品发布 SOP，而是一个可以伴随每个产品、每个创业项目反复复用的 **Product OS**。它将**原则、决策、执行、度量、复盘、知识沉淀**串联成一个闭环，构成长期创业与构建产品的知识体系基础。

整个体系由五大核心层组成。

---

## 01. Principles（产品核心原则）

决定什么情况下该继续，什么情况下该停止。这是体系的最高指南，必须放在任何执行的最前面。

### 1. Problem First
永远不要从 Idea 开始。
`Problem` → `Customer` → `Validation` → `Solution` → `Product`
*(绝不能是：Idea → Coding → Launch)*

### 2. Validate Before Build
任何功能在写代码前都必须先验证。
`Talk` → `Prototype` → `Landing` → `Pre-order` → `Build`

### 3. Revenue > Users > Features
对于独立开发者和创业者，优先级排序如下：
`Revenue` > `Retention` > `DAU` > `Feature Count`

### 4. Ship Weekly
每周必须有一次对外的交付或发声：
`发布` / `Demo` / `Tweet` / `Blog` / `Changelog`。绝不闭门造车。

### 5. Every Phase Has Exit Criteria
只有达到该阶段的**退出标准（Exit Criteria）**才能进入下一阶段。否则，留在当前阶段继续循环验证。

---

## 02. Product Lifecycle（标准化各阶段结构）

拒绝线性、盲目的 Checklist。生命周期中的每一个阶段（Phase 0 - 7）都应当遵循以下统一结构：

### 统一阶段模板 (Phase X)

- **Objective（目标）**：这一阶段的核心目的是什么。
- **Why（为什么做）**：做这件事背后的深层动因。
- **Inputs（输入条件）**：进入该阶段需要什么（例如：*3 个问题 → 5 个访谈 → 竞品分析*）。
- **Deliverables（交付物）**：结束时输出的产物，用于沉淀知识库（例如：*ICP、JTBD、Landing Page*）。
- **Checklist（执行清单）**：具体的待办事项。
- **Metrics（KPI）**：当前阶段要看的量化数字（例如：*访谈人数、Landing 转化率、Email 订阅数*）。
- **Decision Gate（决策点 - 最重要）**：允许失败和退回。例如：*“有没有人愿意付钱？” → YES → 继续；NO → 重新找 Problem。*
- **Risks（最大风险）**：时刻提醒当前阶段最容易踩坑的点。例如：*伪需求、访谈对象错误、MVP 做得太大等。*
- **Exit Criteria（退出标准）**：什么时候算真正结束。
- **Common Mistakes（易犯错误）**：此阶段最不该做的事。例如：*一上来就开始写代码、只找朋友访谈等。*
- **AI Workflow（AI 工作流）**：如何利用 AI 加速此阶段（见下方详述）。

### 关键阶段的量化与风险示例

| Phase | 核心 Metrics | 最大的 Risk | 关键 Decision Gate |
| --- | --- | --- | --- |
| **Phase 1** | Problems Found, Competitors, Interview Requests | 伪需求 | 这是一个真痛点吗？ |
| **Phase 2** | Interview Count, Landing CVR, Pre-order | 访谈对象错误 | 有没有人愿意预购付钱？ |
| **Phase 3** | Build Time, Core Feature Usage, Activation | MVP 做太大 | 5 个首批用户真的完成了核心流程吗？ |
| **Phase 4** | Visitors, Signup, Activation | 没有 Distribution | 用户能否顺畅地被激活？ |
| **Phase 5** | Retention, Referral, MRR | 没有 Retention | 用户留下来了吗？ |
| **Phase 6** | LTV, Churn Rate | 没人愿意续费 | 商业模式可规模化吗？ |

### 融入 2026+ 的 AI Workflow

AI 不再是辅助，而是 SOP 的底层引擎：
- **Phase 1 (发现)**：`Reddit / Social Media` → `GPT` → `聚类分析` → `输出 Problem List`
- **Phase 2 (验证)**：`Interview` → `AI Summary` → `提取 JTBD` → `生成 Persona`
- **Phase 3 (开发)**：`Claude Code` → `Codex / Copilot` → `Cursor` → `Build`
- **Phase 4 (发布)**：`AI 生成：Product Hunt 结构, Blog, Tweet, SEO 策略`
- **Phase 5 (迭代)**：`导入 Analytics` → `AI Retention 分析` → `Review 总结` → `生成 Roadmap`

## 03. Weekly Operating Loop（每周运营循环）

长期打造产品不是线性的通关游戏，而是周而复始的飞轮。

- **Monday**: Research（调研与观察）
- **Tuesday**: Interview（访谈与沟通）
- **Wednesday**: Build（专注开发与构建）
- **Thursday**: Ship（发布与交付）
- **Friday**: Measure（衡量与追踪数据）
- **Weekend**: Review（复盘与下周规划）

## 04. Knowledge Base（知识沉淀 Artifacts）

SOP 每走一步，都必须留下结构化的文档。几年以后，这个 Knowledge Base 将是你最值钱的资产。

| 阶段 | 沉淀产物 (Deliverables) |
| --- | --- |

| **Phase 2** | Interview Notes、JTBD、Persona |
| **Phase 3** | PRD、Architecture、MVP Spec |
| **Phase 4** | Launch Checklist |
| **Phase 5** | Metrics Dashboard |
| **Phase 6** | Pricing Strategy |
| **Phase 7** | Growth Playbook |

## 附：Weekly Review（每周复盘）

一年下来，这将拉开成长的差距。每周日回答以下问题：

1. **本周最大的学习是什么？**
2. **本周最大的错误是什么？**
3. **本周最大的增长点是什么？**
4. **本周最大的收入/转化来源是什么？**
5. **当前面临的最大风险是什么？**
6. **下一周的「唯一关键目标（One Metric That Matters）」是什么？**
