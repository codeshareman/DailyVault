# 2026

2026 年的每日记录与周期计划/复盘均存放在此目录；每日记录 `2026/YYYY-MM-DD.md` 是唯一事实来源，周期文件只从这些页面派生。

```text
2026/
├── 2026-08-17.md # 每日记录
├── Weekly/       # 周计划与复盘（2026-W34.md）
├── Monthly/      # 月计划与复盘（2026-08.md）
├── Quarterly/    # 季计划与复盘（2026-Q3.md）
└── Yearly/       # 年计划与复盘 + 年度统计（2026.md、2026 统计.md）
```

## 周期文件怎么用（一期一文件）

**期初**：QuickAdd「创建周/月/季/年计划与复盘」在对应子目录用 `Templates/{weekly,monthly,quarterly,yearly}.md` 创建文件，Templater 填充日期 frontmatter，先填「本期计划」（≤3 项）。

**期内**：把本期计划拆解到各天的「今日计划」，计划文件不需要重复维护。

**期末**：在同一文件补「本期总结」与「下期重点」（即下一期计划）。

## 两种生成方式

**半自动（骨架）**：期初 QuickAdd 创建文件 → 填「本期计划」→ 期末在同一文件补「本期总结」「下期重点」。

**全自动（AI 生成内容）**：让 AI 调用 `period-review` skill——它读取该周期全部每日记录（唯一证据源），从真实记录提炼本期总结和下期重点，写入对应的一期一文件（不存在则按模板创建）。

周期文件的 `week` / `month` / `quarter` / `year` frontmatter 决定它归属哪个周期；**创建时的日期填充必须准确**。

周期文件只保留叙事，统计不内嵌——周/月/季模板只带一行指向年度统计的外链。**年度统计** `2026/Yearly/2026 统计.md`（`note_type: stats`）是唯一预置统计，创建年度文件时由 Templater 自动生成，用 `year` frontmatter 匹配每日页面：KPI 概览（记录天数、任务完成率、今日计划达标率、最长连续记录、输入/输出条目）、今年做了什么/没做什么（可跳转）、月度活跃趋势与月度计划完成率（CSS 图表）、知识转化漏斗（输入→学到→输出转化率）、`#kind/...` 条目分类（tag 可点击搜索）和输入/输出完整清单（剪藏是输入的子集；条目可点击跳转来源 daily）。任务按 status 精确区分（[x]/[ ]/[-]），统计按月度聚合，不逐日罗列；周期粒度的细节回看翻每日记录或由复盘摘录。
